    LLM and AI systems

    evalsuite.llm_eval

    Run language models and evaluate LLM systems: cached model calls, agent runs, conversations, quality per cost, and benchmark contamination.

    import evalsuite as es runs = es.run_model(prompts, "openai:gpt-4o-mini") # or "anthropic:claude-…", or any callable es.agent_report(episodes) # success, steps, tool use, cost, with CIs es.conversation_report(dialogues) # per-turn and per-dialogue scores es.cost_quality_report({"a": runs_a, "b": runs_b}) # quality, cost and latency per model es.contamination_check(benchmark_items, training_texts) # n-gram overlap with training data

    run_model calls the provider's official SDK (pip install openai / anthropic; keys come from the usual environment variables and are never stored) or any Python callable, with retries, a small thread pool and an on-disk cache in EvalSuite's cache folder (evalsuite cache info), so re-running an evaluation costs nothing. Responses record latency and token counts for cost reports. Intervals in the reports are Wilson intervals for rates and cluster-bootstrap percentile intervals (by dialogue / episode) for means.

    run_model 

    run_model(prompts: Sequence[Any], model: Union[str, Callable[[str], Any]], *, system: Optional[str] = None, cache: bool = True, concurrency: int = 4, retries: int = 3, ids: Optional[Sequence[Any]] = None, **params: Any) -> list[dict[str, Any]]

    Run model on every prompt and return one record per prompt: id, prompt, prediction (the output text), latency_s, input_tokens, output_tokens and cached. model is "openai:<model>", "anthropic:<model>", or a callable taking a prompt and returning text (or a dict with output and optional token counts). prompts may be strings or records with prompt (and id) such as :func:load_benchmark returns. params (temperature, max_tokens, …) go to the provider and are part of the cache key.

    agent_report 

    agent_report(episodes: Union[Sequence[Mapping[str, Any]], Mapping[str, Sequence[Mapping[str, Any]]]], *, level: float = 0.95, random_state: Optional[int] = 0) -> AgentReport

    Summarise agent episodes, one system (a list of episodes) or several (mapping name → list). Each episode is a dict with success (bool) and optionally steps (int), tool_calls / expected_tool_calls (lists of {"name", "arguments"} for tool-call F1), invalid_tool_calls (int), cost and latency_s.

    conversation_report 

    conversation_report(dialogues: Sequence[Mapping[str, Any]], *, level: float = 0.95, n_resamples: int = 2000, random_state: Optional[int] = 0) -> ConversationReport

    Evaluate multi-turn conversations. Each dialogue is a dict with turns: a list of per-turn scores (numbers in [0, 1], e.g. judge or rubric scores of each assistant reply) or of dicts with score; and optionally success (did the whole conversation achieve its goal). Reports the mean turn score, the share of dialogues with every turn acceptable (score ≥ 0.5), the worst-turn mean, goal success, and the mean score by turn position (does quality drift over long conversations?).

    cost_quality_report 

    cost_quality_report(runs: Mapping[str, Sequence[Mapping[str, Any]]], *, prices: Optional[Mapping[str, tuple[float, float]]] = None, level: float = 0.95, random_state: Optional[int] = 0) -> CostQualityReport

    Per model: mean quality (each record's correct (bool) or score), cost per item and latency, with intervals. Cost comes from each record's cost, or from input_tokens / output_tokens and prices[model] = (price per 1M input tokens, price per 1M output tokens).

    contamination_check 

    contamination_check(items: Sequence[Any], corpus: Union[Sequence[str], Any], *, n: int = 13, threshold: float = 0.5, level: float = 0.95) -> ContaminationReport

    Share of each benchmark item's word n-grams that also occur in corpus (an iterable of training texts; streamed, so it can be large). Items are strings or records with prompt / question / text (and id). 13-grams follow the GPT-3 / GPT-4 contamination analyses; items shorter than n words are checked as a whole. An item is flagged when the overlap is at least threshold.

    evalsuite.judging

    LLM-as-judge evaluation in one report: who wins, and whether the judge can be trusted.

    judge_report(records) takes pairwise judgements (one record per comparison) and returns:

    • Win rates of every model with Wilson intervals, the pairwise win matrix and Bradley–Terry ratings with bootstrap intervals (comparisons resampled).
    • Position bias: how often the verdict survives swapping the order (verdict_swapped), and whether the inconsistent verdicts favour the response shown first (two-sided binomial test).
    • Length bias: how often the longer response wins decisive comparisons (binomial test against 0.5).
    • Self-preference: when the judge is itself one of the models (judge), how much more often it picks its own outputs than other judges or humans do on the same comparisons.
    • Agreement with humans (human verdicts): raw agreement (Wilson) and Cohen's kappa (bootstrap interval).

    rubric_report(records) summarises rubric scores (one record per item × criterion × model, optionally per rater): the mean per model and criterion with t intervals, inter-rater reliability (Krippendorff's alpha) and correlation with human scores.

    Every bias is reported with its test and is flagged only when significant, so a report does not cry wolf on small samples.

    judge_report 

    judge_report(records: Any, *, level: float = 0.95, alpha: float = 0.05, n_resamples: int = 1000, random_state: Optional[int] = 0) -> JudgeReport

    Pairwise LLM-judge evaluation. Each record: model_a, model_b, verdict ("A", "B" or "tie", naming the response by identity) and optionally verdict_swapped (the verdict when the two responses were shown in the other order, again by identity), length_a / length_b (or response_a / response_b to measure them), judge (the judge model's name) and human (a human verdict on the same comparison).

    rubric_report

    Rubric scores: records with id (item), model, criterion, score and optionally rater (several raters per item and criterion give inter-rater reliability; scale is Krippendorff's level) and human (a human score for the same item, model and criterion).

    evalsuite.rag_report

    End-to-end RAG evaluation: retrieval, grounding and answer quality in one report, with every failure traced to the stage that caused it.

    rag_report(records, k=5) takes one record per question:

    • retrieved — ranked document ids; relevant — the ids that answer the question (optional);
    • answer — the system's answer; reference — the gold answer (a string or a list of acceptable answers);
    • grounded (true / false) or support (per-claim 0 / 1 or scores in [0, 1], e.g. from an NLI model or an LLM judge) — whether the answer is supported by the retrieved context (optional).

    It reports hit rate, recall and MRR at k, exact match and token F1, the grounded rate, each with an interval, and classifies every question:

    • correct — right answer, supported by the context (or no grounding data given);
    • retrieval_failure — wrong answer and no relevant document in the top k: fix the retriever;
    • generation_failure — wrong answer although a relevant document was retrieved: fix the prompt / model;
    • unsupported_correct — right answer that the context does not support (memorised or lucky);
    • wrong_unknown_cause — wrong answer without relevance labels to tell retrieval from generation.

    The breakdown (with Wilson intervals) says where to invest, and examples lists the ids in each class.

    evalsuite.llm_benchmarks

    Ready-made LLM benchmarks: the scorer, references, categories and prompts of common evaluation sets.

    import evalsuite as es items = es.load_benchmark("gsm8k", limit=200) # needs pip install datasets

    ... run your model on item["prompt"], store {"id": item["id"], "prediction": output} per model ...

    board = es.leaderboard({"model-a": runs_a, "model-b": runs_b}, benchmark="gsm8k", references=items)

    benchmark= sets the scorer (GSM8K's final-number match, letter matching for multiple choice, pass@1 for code) and, with references from :func:load_benchmark, per-subject categories. Datasets are downloaded from the Hugging Face Hub by the optional datasets package and are never bundled. Runs that already contain reference (or correct) need no download at all.

    HumanEval completions must be executed to be scored. EvalSuite never runs model-generated code: run them in your own sandbox (for example the official human-eval harness) and pass passed (true / false) per item, or n_samples and n_correct for an unbiased pass@k estimate.

    evalsuite.harness

    A statistically careful LLM evaluation harness.

    Point it at each model's outputs (JSONL files, lists of records or DataFrames) and it scores them, puts an interval on every number and only ranks models apart when the difference is significant:

    • every model's score with a Wilson (or bootstrap) confidence interval;
    • paired tests between models on the items they share (exact McNemar for correct / incorrect, a paired bootstrap for graded scores), with Holm-adjusted p-values;
    • rank groups: a model's rank is 1 + the number of models significantly better than it, so statistical ties share a rank;
    • per-category breakdowns with intervals;
    • checks: unmatched or missing items, extraction failures, contamination (n-gram overlap of each item with a training corpus you provide, and scores on clean versus overlapping items), and judge position bias when the records carry verdicts in both presentation orders.

    Each record is a mapping with an id and either a correct / score value from your own grader, or a prediction (model output) scored against the reference (gold answer) with scorer. Optional fields: category, prompt (for the contamination check), verdict and verdict_swapped (judge verdicts "A" / "B" / "tie" with the two answers in the original and the swapped order).

    import evalsuite as es runs = { ... "model-a": [{"id": i, "prediction": "4", "reference": "4"} for i in range(30)], ... "model-b": [{"id": i, "prediction": "4" if i % 3 else "5", "reference": "4"} for i in range(30)], ... } lb = es.leaderboard(runs, scorer="exact_match") best = lb.rows[0] best.get("model"), best.get("rank") ('model-a', 1)

    Leaderboard dataclass

    Scores with intervals, paired tests, rank groups, per-category results and data checks.

    leaderboard 

    leaderboard(runs: Mapping[str, Records], *, scorer: Optional[Union[str, Callable[[str, str], Any]]] = None, references: Optional[Records] = None, benchmark: Optional[str] = None, level: float = 0.95, alpha: float = 0.05, correction: str = 'holm', train_corpus: Optional[Iterable[str]] = None, ngram: int = 13, n_resamples: int = 2000, random_state: Optional[int] = 0) -> Leaderboard

    Score several models' outputs and rank them with intervals and paired tests (see the module docs).

    runs maps model names to records (a JSONL / JSON path, a list of dicts or a DataFrame). references optionally supplies the gold answers separately (records with id and reference). scorer is one of "exact_match" (SQuAD-normalised), "contains", "gsm8k", "boxed", "choice", "last_line", "numeric", or a callable (prediction, reference) -> score in [0, 1]; records with a correct or score field are used as given. train_corpus (iterable of texts) enables the contamination check. benchmark ("gsm8k", "mmlu", "arc", "arc-easy", "truthfulqa", "humaneval") picks that benchmark's scorer (unless scorer is given); pass references=es.load_benchmark(name) for its gold answers and categories. For HumanEval, records carry passed (or n_samples / n_correct) from your own sandboxed execution; the score is pass@1.
